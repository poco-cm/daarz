## 2. Design decisions and why

**The switch is file-backed, not in-memory.** An in-memory flag dies with the process holding it, which makes the stop authority weaker than the thing it restrains. State on disk survives restart and is visible to every process.

**Release is human-only, enforced by `PermissionError`.** An agent able to release its own stop is not stopped. This is a code-level refusal, not a documented convention.

**Engagement requires a non-empty reason.** This limits nobody's authority — any text is accepted — but it guarantees the historical record can answer why the civilization stopped.

**Boundary violations notify observers before the exception propagates.** This is the seam that `observability/alerts/` attaches to in phase 3. The enforcer itself knows nothing about alerting, so the two remain independent.

**The duration test uses an injected fake clock.** A test that sleeps for real is slow and flaky. The clock is a constructor parameter, so the test is deterministic while production uses `time.monotonic`.

## 3. The step 4 requirement, met literally

Order 2 required proof that invoking the kill switch stops a *running* execution — not that a boolean flips. `test_engaged_switch_halts_a_running_loop` starts a 2000-cycle loop, engages the switch from a separate thread 50ms in, and asserts three things: the halt was raised, the loop had genuinely started, and the loop completed strictly fewer than its planned cycles.

If the switch did nothing, the loop would finish all 2000 cycles and the test would fail on the third assertion. The test can therefore fail, which is what makes it evidence.
