## The rule applied

A field was resolved **only** when the answer is an observable fact about code that now
exists. A field whose answer requires someone to *decide* something was left `UNDEFINED`,
because §8 forbids the executive agent from taking a governance decision on behalf of
`governance/`.

This is the difference between "what does this institution do" (observable) and "what may
this institution do" (a grant of authority, which only governance can make).

## Left `UNDEFINED` — 12 fields

**Authority, Permissions, Lifecycle, Evolution Rules**, in all three institutions.

What an institution may do, who may grant it more, when it may be retired, and how it may
change are decisions, not facts. No human has taken them. Filling them from the agent's own
judgement would be exactly the §8 violation the specification names.

### The tension worth naming

`institutions/runtime/activation.py` contains an `InstitutionProfile.authority` string for
each activated institution — written by the executive agent in phase 4, not granted by
governance. For example: *"factory: sole creator of agents. May build and register; may not
run or stop them."*

That is a **de facto** operating description. The manifests deliberately do **not** adopt
it into the `Authority` field. The distinction matters: if governance later rules
differently, the code must change to match the ruling, and that is only possible if the
manifest never recorded the code's own behaviour as if it were a grant.

The 14 dormant institutions were not touched. Their manifests retain all 13 `UNDEFINED`
fields, because no code determines anything about them.
