## Problem

Spec §8 states that the executive agent may not "create any root directory or new pattern not mentioned here without passing the §7 pipeline", and may not write real executable logic. Whether this content was authored by an agent or inherited from a platform template does not change its status: as of today it is unratified, and while it stays unratified the Genesis exit test cannot pass.

## Why the executive agent cannot resolve this

Spec §8 prohibits the executive agent from taking a governance decision on behalf of `governance/`, and from deleting anything without a direct explicit human order. Ratification and removal are both governance acts. This proposal therefore stops at stage 1 and awaits a human decision.

## Options

**Option A — ratify as a documented exception.** Declare this content an infrastructure annex outside civilizational scope, record it permanently in `archive/decisions/`, and amend the specification through the §7 pipeline to name it. Preserves all existing work. Cost: the specification stops being the single source of truth about the repository's shape until the amendment lands.

**Option B — isolate.** Move the content into one explicitly ratified root directory, or into a separate repository, leaving the civilization tree clean. Cost: a migration with real breakage risk for anything currently depending on those paths.

**Option C — remove.** Cleanest conformance, highest cost, irreversible. Requires a direct explicit human order under Spec §8.

## Recommendation

Option A, on the grounds that the content is genuinely infrastructural rather than civilizational, and that Option C destroys working code to satisfy a document that can instead be amended honestly through its own pipeline.

Architectural Analysis → Impact Analysis → Compatibility Analysis → Security Review → Governance Approval → Migration Plan → Implementation → Tests → Promotion.

All nine stages completed on 2026-08-09. Outcome: Option A, ratified with binding isolation conditions. This proposal is closed.
